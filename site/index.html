Les pains

Quatre façons dont les agents IA cassent en production

Les équipes déploient des agents IA depuis deux ans. Les échecs suivent quatre patterns reproductibles. Aucun n'est résolu par les modèles. Tous sont résolus par une couche de gouvernance.

01

Agent runaway — $847 brûlés en 52 minutes

Un agent LangChain mal calibré tourne en boucle pendant que vous dormez. À 3h du matin il a épuisé votre quota OpenAI du mois. Personne ne surveille le coût par agent en temps réel. La plupart des frameworks d'agents n'ont aucun kill-switch budgétaire natif. Orchestre coupe l'exécution quand le coût dépasse le seuil, persiste l'état, et permet la reprise.

02

Pas d'audit trail — "que faisait l'agent quand c'est cassé ?"

Un agent de support client a répondu quelque chose d'illégal à un utilisateur. Vous n'avez ni trace de sa décision, ni log des tools appelés, ni état intermédiaire. L'EU AI Act entré en vigueur fin 2025 impose des audit trails exploitables pour tout système IA à risque élevé. Orchestre persiste chaque événement en append-only log, rebuildable, exportable pour audit légal.

03

Permissions trop larges — l'agent peut tout faire

Votre agent a accès à tous vos outils : Slack, GitHub, Jira, filesystem, API internes. Une hallucination, une prompt injection, et il envoie un message gênant dans #general ou supprime un repo. La sécurité par défaut est l'exception, pas la règle. Orchestre applique des permission gates par phase : l'agent ne voit que les tools dont il a besoin, au moment où il en a besoin.

04

Pas de mémoire des échecs — les mêmes bugs reviennent

Chaque run d'agent repart de zéro. Si votre agent a produit 50 fois du code avec any type, rejeté 50 fois, il va le reproduire la 51e fois. Aucune capitalisation sur les corrections passées. Orchestre maintient une mémoire procédurale — chaque rejet ≥ 3 fois devient un pattern à éviter, injecté dans les prompts suivants.

L'approche

Un runtime de gouvernance, pas un framework de plus

Orchestre n'essaie pas d'être plus intelligent que votre modèle. Il rend votre modèle déployable en production en lui imposant quatre contraintes non-négociables.

Contrainte 1

Budget borné

Chaque agent s'exécute avec un quota USD maximum. Le runtime coupe l'exécution à 120% du seuil, persiste l'état, et permet la reprise manuelle.

Contrainte 2

Permissions minimales

Par phase d'exécution, le runtime définit un allow-list de tools. Toute tentative d'accès à un tool non-autorisé lève une exception auditée.

Contrainte 3

Audit trail append-only

Chaque décision, chaque call LLM, chaque tool invocation écrit un événement immuable. Rebuildable, exportable, conforme EU AI Act.

Contrainte 4

Mémoire procédurale

Les patterns rejetés sont persistés et injectés dans les prompts futurs. L'agent s'améliore à chaque run au lieu de répéter les mêmes erreurs.

Preuves

Open source, testé, auditable

Pas de promesse marketing. Le code est public, les tests sont verts, le runtime tourne sans dépendance externe.

À propos

Qui je suis

Je m'appelle Chady Emara. Je construis des systèmes d'infrastructure pour l'IA depuis 2024. Orchestre est mon projet principal : un runtime open-source de gouvernance pour agents IA, utilisé pour enforcer budget, permissions et audit trail sur n'importe quel système agentic.

Mon pari : la valeur de l'IA en production ne sera pas dans les modèles — elle sera dans la couche qui rend les modèles déployables. Contrôle des coûts, isolation de sécurité, traçabilité pour la compliance, apprentissage des échecs. Cette couche existe à peine aujourd'hui. Je la construis.

Avant Orchestre, j'ai travaillé sur des architectures logicielles clean-architecture et des outils pour développeurs. Je parle français et anglais. Basé à Paris. Disponible pour interventions, conférences et missions d'audit en France et à l'international.
